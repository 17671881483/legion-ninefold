## 每项任务的验收规则

1. **来源**：原始 JASS SHA-256 为 `e66c55b3b25b185c991be5613e21fbf5b2d598f3cc40f2f8cd01c23bcb828250`。路径 `reference/v14-source/raw_extracted/war3map.j`；按字节 Latin-1 解码并只按 LF 分行，避免 `splitlines()` 因原始字节 `0x85` 改变行号。字段、源码、文案和推断分别记录。
2. **入口**：确认函数确实被注册/调用，不因存在函数定义就接入；能力 rawcode 保留大小写，建筑体与战斗体区别校验。动态授予能力、召唤体与运行时形态纳入覆盖。
3. **行为**：覆盖正反条件、随机边界、重复触发/禁止重入、死亡与移除差异、范围及阵营、护甲/魔免、冷却/资源、任务结束与保存恢复；不写只重复实现表达式的测试。
4. **状态**：逐项说明已实现、部分实现、仅标记、待核定的依据。缺少原生默认值或可验证运行结果时不能用文案补造数据，也不能将缺失字段默认为零后标完成。
5. **回归**：先运行本家专项及受影响事件链测试；主聊天整合后运行 `npm test`、`npm run test:smoke`、`npm run build` 和 `node scripts/stamp-assets.mjs --check`。失败须解决或明确给出阻塞证据。
6. **交付**：功能提交、专项测试、逐行证据、独立交接记录，列出文件、提交号、检查结果、剩余边界和共享接线。完成代码后更新相关清单；主聊天负责最终验收与发布。
