## 来源与行为

[来源证据](../../reference/phoenix-revival-evidence.json)固定原始 JASS 文件 SHA256、行号及对象字段。`PhoenixReviveAction` 位于 31877—31945 行，登记函数位于 31946—31956 行，`PassiveSkill` 在 43818 行检查建筑 A1SE。

- 普通出战、竞技出战均由建筑 A1SE 登记 EVENT_UNIT_DEATH；战斗体只有同名能力不补造登记。ACrn 等待复生触发 widget 死亡时不提前触发此链。
- 死亡时检查当前 A1SE 等级；有效则对 SelectRange400 中的敌人造成 102 混乱／通用伤害，保留 BJ 的 attack=true，再创建 h0VY 凤凰蛋、移除旧体。
- 3 秒后先 KillUnit 凤凰蛋，再以蛋的所有者、坐标、朝向、userData 创建 h0VZ，最后移除蛋。第一次新体重新授予 A1SE 并登记死亡；第二次结束监听。两次新体均为 2000 生命、190 平均基础攻击、30 魔法，不按提示再次减半。
- 蓝色 h0WW 的标记穿过两次新生，普通 h0VX 与蓝色本体均使用同一个 h0VZ 原型。新体不复制旧 buff、临时属性、建筑 ID 或行军命令，不凭空增加召唤物标签。
- 爆炸发生在死亡时，不在孵化时；没有额外 56 灼烧。提前死亡但仍有保留句柄的蛋到期仍尝试孵化；主动移除蛋的原生结果未核定，宿主停止该任务并保留边界。

## 原生边界与交接

凤凰蛋原型缺少 spd、weapsOn 字段，缺失不等于 0；不能使用导入器通用的 270 移速和开启武器回退。当前明确采用静止等待的宿主适配并保留未知字段标记，不声称原脚本调用 PauseUnit。原生碰撞、科技对新体属性、死亡监听顺序、已移除句柄、原始模型资源仍待核定。Canvas 只提供凤凰蛋与新体的替代表现。

A1SB 烈焰打击和 A1SC 火之羽仍待实现，此项不代表凤凰整个家族完成。上下文在本文件归档，主聊天继续未完成的整体还原目标；原三个开发聊天保持归档。
